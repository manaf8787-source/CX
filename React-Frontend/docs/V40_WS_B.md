## 4. Foundation requests

1. `routes/pages.test.ts` counts the `// FOUNDATION STUB: owner = workstream X` markers (10 files). The brief says to remove a marker when a stub is replaced; doing so fails that test (it already fails for `AsOfBar.tsx`). I **kept** the marker line in `TraceHost.tsx` and `EscalationMatrix.tsx` (reworded "replaced by workstream B") so the test passes for my two. Drop or rewrite that test when A, B and C have landed.
2. `Signal` has no severity and no source field, so the dialog's "severity" chip is missing and "source" is the signal type plus the channel of the events that produced it. If the chip is wanted, add `Signal.severity` (and `source`) to the sample.
3. `useFixDue(fix)` for an approved or later **sample** fix that has no `dueSource` returns a preview from now, not the stored date. I read `fix.dueDate` for any status but `proposed` and use `useFixDue` only for the preview. Better inside the hook: return the stored date whenever the status is past `proposed`.
4. `createActionFromPattern` still requires `dueDate`. The dialog passes the preview date (approval overwrites it). Make `dueDate` optional, or fill it in the mutation from the matrix.
5. `components/ui/dialog.tsx` close button has an English-only screen-reader label ("Close"): in Arabic the dialogs announce it in English. Use `t('Close', 'إغلاق')`.
6. `data/v38Reference.ts`: `ESCALATION_ROWS` and `ESCALATION_COLUMNS` are now unused (only `ESCALATION_PRINCIPLES` is read, by Rules). `SectionCard` has no `id` or anchor prop (I wrapped the Patterns card in a `div#patterns`).
7. `TraceKind` has no investigation: the `INV-n` tag is a local span.

## 5. Known gaps

- No "confirm this default as it is" on a matrix cell: an owner has to retype or change the value for the badge to go. Matrix edits live in the session, as in the prototype; they are not audited.
- Fix cards are always fully open (next step, matrix line, classification, AI panel, audit trail, Trace card): the fixes tab is long. A collapse per card is a design call I did not make.
- No verdict buttons (effective, partial, failed): that is Agent 6's call; only the seeded verdicts exist.
- The signals table is plain (search, sort by date, 8 per page); no filters.
- The event link depends on the Customers page rendering the timeline for `/customers/:id?ev=`; the e2e covers it with the current Customers page.
- "Due" dates use the browser locale format.
- `docs/FIDELITY_REVIEW.md` and `docs/IMPLEMENTATION_REPORT.md` are not updated (documentation pass).
