## 2. Sidebar: open, close, scroll

| Part | How |
|---|---|
| State and layout | `rail` (the state: column width, `aria-expanded`, tooltips, storage) changes at once. `layoutRail` (which layout is drawn, `data-collapsible`) follows at once when opening and `CLOSE_MS` (440ms) later when closing. `data-phase` on the `nav` is `opening`, `closing` or `settling` only while it moves |
| Opening | The expanded layout is laid out at its full width (200px) at once and the widening column reveals it, so no word re-flows or is cut to "Ho…". The words fade in top to bottom (`.nav-fade`, `--nav-i` sets each row's delay). Column: 680ms on `--ease-smooth` (no overshoot) |
| Closing | The words fade out, the column narrows, then the rail layout takes over and its two own buttons fade in (`.rail-fade`) |
| Reduced motion | No phase: it opens and closes at once |
| Scrolling | The menu list scrolls by wheel, touch and keyboard with no bar of its own; `useScrollFade('y')` sets `data-fade-start` / `data-fade-end` and the mask fades that edge. The active item is brought into view when the route or the list changes (only the menu scrolls) |
| Rail link names | A link's label is `sr-only` in the rail, not `display: none`, so the link keeps its accessible name there |
| Dev server | `vite.config.ts` no longer watches `dist*`, `playwright-report*`, `test-results*`: a test run was reloading the open page for every report file |

Files: `components/layout/Sidebar.tsx`, `Shell.tsx`, `components/ui/use-scroll-fade.ts`, `styles/theme.css` (`--ease-smooth`, `no-scrollbar`, `scroll-fade-y`, `.nav-fade`, `.rail-fade`, `nav-fade-in`).

## 3. Glass

A well was a flat `#f2f2f2` patch with no shadow (the skill's rule). It is now a pane of glass: the well tone under a diagonal sheen (`--grad-glass`, light from the top corner), a white inner rim, a hairline, and a soft drop (`--shadow-glass-well`); a clickable one lifts on hover (`--shadow-glass-well-hover`). Dark theme: the same with white at 10% to 0%.

| Token | Light | Dark |
|---|---|---|
| `--grad-glass` | white 94% → 55% → 6%, at 145° | white 10% → 4% → 0% |
| `--glass-rim` | white 80% | white 6% |
| `--glass-edge` | black 5.5% | white 7% |
| `--glass-drop` | black 16% | black 55% |

`.well` applies it with its padding and radius; the `glass` utility is the material alone, used by blocks that set their own box: the six step tiles on Home, a timeline row, a glossary entry, a view-only note, the role rows of the sign-in screen. No `backdrop-filter`: a well sits on a plain card, so a blur would cost paint time and show nothing **[Proposed]**. Chips, tags, input fields, tracks and avatars are not boxes and keep their own materials.

## 4. Language and theme

| Control | Before | Now |
|---|---|---|
| Language | One button that named the language you would switch TO | A two-key switch, `EN` and `ع`: both show, the dark key is the one in use, one click picks the other. A radio group named "Language"; the keys are named "English" and "العربية" |
| Theme | An icon button that opened a menu of three modes | A three-key switch: light, dark, match device. A radio group named "Theme". Where the top bar is narrower than 900px (tablet, phone) it is one round button that steps light → dark → device and names the next mode |

`Segmented` gained `compact` (narrow keys) and per-option `ariaLabel`, `title`, `lang`. The search field's maximum width went from 280 to 240px to make the room. Both switches are also on the sign-in screen.

## 5. Guided tour

| Part | Change |
|---|---|
| Frame | One frame for the whole tour, held by `TourHost`: it glides from one element to the next (520ms, `--ease-smooth`), then follows its element frame by frame. When a step changes page the frame is dropped first |
| Card | Fades and rises on `--ease-smooth`, 140ms after the frame starts to move (it was a spring with overshoot) |
| Placement | New `side` placement: when the card fits neither below nor above (a tall card on a short screen) it stands beside the element, reading-order end first. It sits on the element only when the element is as large as the screen |
| Short screens | A tall element's frame shrinks so the card fits under it (`tallFrame`); a middling element is put under the top bar when that makes room for the card |

## 6. Logo

Source: `React-Frontend/logo/CX_LOGO_LIGHT.svg` and `CX_LOGO_DARK.svg` (the owner's files; the PNGs in that folder are not used by the app). The two files differ only in the fill of the letters, so `components/common/BrandLogo.tsx` draws the letters in the text colour (`currentColor`) and serves both themes. The point keeps the logo's orange (`--brand-point`, `#e0592a`): the only place that colour appears.

Animation: the point leaves its notch at the top of the C, travels once round the letter (anticlockwise, through the body and back across the opening), swells a little as it lands, rests, and goes again: 5.6s a turn, for ever. It stands still under reduced motion.

`public/favicon.svg` is the logo on an ink tile.

## 7. One correction found on the way

The automatic readout beside a fix's 60-day check called a 38% drop "Effective": it used 25% and 10% thresholds carried over from the old scaffold. It now follows the rule on the Rules page (`rule_effective_drop`, 50%): half or more reads effective, a smaller drop partial, no drop failed. **[Proposed]**: the line between partial and failed is "any drop", since the rules define only the 50% line. Files: `utils/effectiveness.ts`, `utils/ruleValues.ts`, `FixCard.tsx`, `MonthlyPack.tsx`, the sample builder.
